# برنامه آزمون مستقل — MCI Expo Leads

**کامیت ممیزی‌شده:** `c6a1c88de0c243015941a166b22211c500543d59` · **شاخه ممیزی:** `qa/audit-c6a1c88`
**نقش:** ممیزی مستقل QA، امنیت، دسترس‌پذیری و تجربه کاربری به‌همراه اصلاح.

## ۱. دامنه
- همه مسیرهای برنامه (۲۲ مسیر) و جریان‌های اصلی: ورود/خروج/بازنشانی رمز، زمینه رویداد، ثبت سریع، فهرست و جزئیات لید، تکمیل اطلاعات پس از رویداد، ارجاع کامل، وظایف، پیام و درخواست اقدام، تنظیمات اعلان و سرویس‌دهنده، خروجی، آفلاین، مدیریت رویداد/کاربر/برچسب/نشان.
- مرز مجوز سمت سرور: ماتریس API (۲۰ عملیات حساس × ۹ پرسونا) شامل IDOR افقی (رویداد A↔B) و ارتقای عمودی.
- امنیت: CSRF، XSS، بارگذاری فایل، محدودیت نرخ، نشست، سرآیندها، نشت داده بین رویدادی، تزریق فرمول در خروجی.
- قابلیت اطمینان: صف خروجی تراکنشی، Celery واقعی روی Redis، حذف تکرار، مهاجرت‌ها و بازگشت آن‌ها، پشتیبان/بازیابی.
- کارایی: تأخیر API (P50/P95) و LCP موبایل در شرایط شبیه‌سازی‌شده — **اندازه‌گیری محلی، نه تولید**.

## ۲. خارج از دامنه / مسدود
- WebKit و Firefox: باینری‌ها در محیط وجود ندارد و نصب Playwright ممنوع است ← **BLOCKED** (روش فعال‌سازی: `npx playwright install webkit firefox` در محیط مجاز؛ پروژه‌ها در `qa.config.ts` خودکار فعال می‌شوند).
- ساخت Docker: daemon در دسترس نیست ← **BLOCKED** (اعتبارسنجی `docker compose config` انجام شد).
- دستگاه فیزیکی: انجام نشد؛ همه آزمون‌ها شبیه‌سازی (emulation) کرومیوم هستند.
- ارسال واقعی پیامک/ایمیل: عمداً انجام نشد؛ فقط سرویس‌دهنده‌های Mock.

## ۴. داده آزمون (کاملاً ساختگی)
پایگاه داده جداگانه `expo_leads_qa` با `seed_demo` + `seed_qa`. پرسوناها:
مدیر سامانه (`admin`)، مدیر توسعه بازار (`mdm`)، مدیرکل عملیاتی (`dg` — دو رویداد فعال)، ناظر فقط‌خواندنی (`exec`)، مدیر رویداد (`evmgr`, `qa_evmgr2`)، مدیر طرح (`planmgr` — هم ثبت‌کننده و هم گیرنده ارجاع)، مالک محصول (`owner`)، کارشناس غرفه (`specialist1/2`)، کارشناس دو رویدادی (`qa_dual`)، کاربر بدون عضویت (`qa_nomember`)، کاربر فقط با رویداد بسته/بایگانی (`qa_closed`). لیدهای لبه‌ای با نام بسیار طولانی و متن مختلط فارسی/انگلیسی/ارقام.
